# 豆包：引用与取证

本指南来自一批实际采集报告，不承诺豆包当前每种界面都一致，不固定依赖私有接口名。

1. 首选页面可见内容、展开引用、复制实际链接。不要因引用不是 `<a>` 就遍历页面全部内部状态。
2. 如果客户端已有受支持的只读网络响应能力，可以读取**当前任务页面、当前题目实际加载的响应**，提取其中的回答或引用。它属于来源证据，但需与页面本题对应。记录取数方式、来源计数和映射依据，不保存请求头、Cookie、令牌、全量账号会话或无关响应。不要主动调用私有接口查询其他会话。
3. 引用标签截断时，优先按响应内明确的 citation 标识对应。只有明确属于同一列表且顺序已核实时才按序号对应；不能凭数组位置或模型知识猜测。无法对齐的引用在 completeness_notes 说明。
4. 页面显示 N 项、实际获得 M 项时，分别记录 N、M、不可解析条目的标记/位置、空卡片现象及截图位置。`citations` 只放有真实 URL 的条目，不用 null URL 或伪造链接占位；状态为 incomplete。空对象可能来自平台、懒加载、未展开或取数路径不完整，采集端不能自行认定 platform_gap、豁免计价或改成 complete。
5. 对单个缺失原因最多尝试两次页面支持的展开/滚动等修复，总排查目标不超过三分钟；仍缺失就上传不完整证据并停止本题。不要为补齐数字反复提问、换号、反向工程私有状态或编写 fetch/XHR 注入补丁。

截图在领题前确认可保存为本机 PNG/JPEG。截图工具输出只有图像展示、没有文件导出能力时，不要让模型人工复制 Base64，也不要尝试宿主机窗口抓屏脚本。报告缺失的能力，交维护者实现明确的浏览器适配器。

“平台缺口”应由负责人复核证据后单独确认，并在今后的任务中预先约定劳动验收、完整数据计数和报酬规则；不自动验收通过。管理员可在待验收样本上填写原因并确认“强制通过”，保留缺项，计入通过配额；正式任务进入待人工结算，不自动付款。参与者不能自行强制通过。
