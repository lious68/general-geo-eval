# GEO 与准活正式任务流程（2026-09-25）

已部署版本：`20260925-geo-workflow`。原 t1 两条试跑记录保留，不补建收费任务、不修改验收结论、不登记付款。

## 负责人使用步骤

1. 在准活发布技能任务，填写报酬、参与人数、期限、说明和验收标准。明确报酬按每条验收通过的样本计算。
2. 在 GEO 后台新建题目项目，配置平台、题目、每题参与人数、每批题数和采集条件，生成任务关联码。
3. 用任务发布者的准活账号进入 `/geo/index.html`，加载自己发布且未被领取的新任务，输入关联码，确认计价方式。关联码十分钟有效，与设备绑定码不同。
4. 关联后，该任务沿用准活大厅、领取、工作台和收件箱。名额限制参与人数；总目标预算为题数 × 每题副本数 × 合格样本单价。关联后单价与名额锁定，不能改写已有约定。
5. 参与者领取后，通过 GEO 页的五步说明安装和绑定星图 Skill。系统分题，星图采集原始回答、引用、条件和截图。
6. 在 GEO 后台按题验收。列表显示项目、题号、题目、平台、准活昵称和账号编号；弹窗内显示缺失原因。允许通过、退回补充、最终驳回。
7. 准活每分钟同步状态与站内提醒。实际转账后，发布者才在 GEO 页登记交易号并确认；这个操作不发起转账，同一样本不能重复登记。

## 本次 pending 的原因及操作

t1 第二题“优刻得轻量云主机怎么样？”的采集说明记录：页面显示 21 条参考资料，其中 6 条无标题和链接，标为 `citations_state=incomplete`。验收拒绝通过符合完整性要求。旧界面错误提示位于弹窗外，已改为弹窗内展示并禁用不完整样本的通过按钮。

负责人填写缺失原因并点击“退回补充”。参与者更新 Skill 后执行 status 读取反馈，让星图恢复原问题会话，补采真实链接和证据，以原 assignment_id 提交新版本。不要重新提问冒充旧回答或编造链接。原始版本保留；无法补齐时保持事实记录，由负责人决定最终驳回。

## 关联与状态约束

- 准活身份从网页登录或设备令牌派生，不接受客户端自报他人账号。
- 用户昵称由准活同步到 GEO；没有增加另一套众包用户账户。
- 已采集的试跑项目不能追溯改成收费任务。正式任务只能关联尚无人领取的新任务。
- 退回补充保留原题配额；补充以新增版本保存，不覆盖原始证据。
- 原生准活整份验收入口不允许覆盖 GEO 逐题状态，会引导进入 GEO 后台。
- 合格样本金额汇总到工作台；验收、付款记录和真实到账含义分别明确。
- 通知使用事件键去重。GEO 验收仍由 GEO 管理员执行，准活发布者通过后台权限访问，不是自动获得 GEO 管理员权限。

## 部署与验证

GEO 应用位于 `/opt/general-geo-eval`；准活 release 位于 `/opt/youhuo/releases/20260925-geo-workflow`，原版本为 `20260925-geo-mask`。两端备份目录为 `/var/backups/geo-crowd/20260925-geo-workflow`。数据库只做新增表迁移。

`geo-workflow-sync.timer` 每分钟运行 `geo_sync.py`，使用已有受限 SSH 服务通道；未新增公网内部接口或交换参与者浏览器凭据。

验证覆盖：准活 156 项回归测试；GEO 全套原 31 项和新增关联/补充回归；双端真实 HTTP 本地集成；服务器独立 PostgreSQL 测试库中的关联、退回、验收、通知去重、结算与防重；公开页面版本与 Skill 包摘要；线上原样本与发布前备份逐字段一致。

本次未替用户操作真实样本验收、建立真实收费任务或登记实际付款；星图参与者电脑上的新版补采仍需实际使用验证。

回滚应用时先停止 `geo-workflow-sync.timer`，将准活 current 切回原 release，恢复 GEO 备份中的代码并重启应用。保留数据库中的新增记录，不用旧数据库覆盖新提交。

## 后续更新：force6 / client6

增加管理员强制通过，仅限 pending，要求原因与明确确认。样本状态为 accepted，review.decision 为 force_accepted，forced_acceptance 为 true；原始回答、完整性标记、条件和阻塞原因不改。该记录计入通过配额，正式关联任务按原约定进入人工结算，不触发实际付款。已有样本未被代为强制通过。

客户端版本 20260925-client6，新增 references/screenshots.md：星图与 WorkBuddy 按实际工具说明保存文件，最多两条路径、三分钟排查，成功方式整批复用；不声称已实现或验证两款客户端所有版本的截图接口。源码通过 41 项测试和前端构建。

## 后续更新：publish7

推荐流程改为 GEO 配置题目 → 带到准活发布 → 自动带入平台、题目快照与采集要求 → 负责人填写报酬、参与人数和截止日期 → 预览确认 → 自动关联后开放领取。题目完整快照保存在准活任务的 geo_publish_drafts，正式任务详情展示完整清单。原有手动关联保留为兼容路径。

一次性关联码放在 URL fragment，预览加载后从地址移除并暂存当前账号的会话草稿。发布失败时不得重复创建任务：同一个项目与发布者复用已创建任务；未关联的导入任务保持隐藏并禁止领取。关联失败会跳转 GEO 页显示原任务编号、原因和重试入口；过期需要从 GEO 重新生成关联码。

技能众包页顶部增加 GEO 入口，已关联 GEO 任务优先排序。预算显示按题数 × 每题副本数 × 样本单价计算，参与名额不作为样本数。发布仍由负责人明确确认，不自动设定金额、名额或期限。

验证包括 41 项 GEO 测试（扩展双端 HTTP 导入/去重/隐藏/关联/题目详情与预算）、156 项准活回归、浏览器模拟接口的预填/预览/发布/关联交互，以及前端构建和生产服务器独立数据库迁移验证。
