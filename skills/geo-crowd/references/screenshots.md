# 星图 / WorkBuddy：截图保存顺序与停止条件

领题前读取本指南。工具名和参数以当前客户端实际工具说明为准，不猜测 API，不把本指南当作已经安装浏览器工具的证明。本 Skill 的设备绑定仍要求 Windows 本机；本指南不能让远程沙箱自动获得本机文件或登录态。

## 共同顺序（整个能力排查最多三分钟、最多两条路径）

1. 查看当前截图工具是否支持文件路径、下载附件或产物导出。能指定 path / output 等参数时，按工具的实际说明直接存到用户已授权的任务工作目录。
2. 浏览器无法直接落盘且本机已装 FFmpeg 时，优先按下方 FFmpeg 分支做一次单帧测试，作为唯一替代路径；不要先尝试模型转录 Base64。否则，工具只返回图片资源时，只使用其文档支持的导出/下载能力取得本机文件。若返回原始二进制或 Base64 且当前工具运行时允许程序直接处理，由程序一次性写文件；不要把 Base64 打印到对话再让模型转录或分段拼接。
3. 验证文件实际存在、大小非零、格式 PNG/JPEG，并打开确认问题与回答文字可辨。路径必须能被运行 client.py 的同一 Windows 用户读取；网页 URL、资源 ID、聊天图片预览不是本机文件路径。
4. 正常路径和一次受支持的替代路径都失败，或三分钟用完，立即停止并报告“截图导出缺失/路径不可访问/截图黑屏”等具体原因。不领取新题，不轮换抓屏库，不新增依赖。已领取则停止发新问题，报告已保存资料并释放剩余任务。

## 星图 AstraFlow

- 先按 SKILL.md 选择独立采集浏览器，优先由 Playwright / CDP 浏览器工具直接保存截图；星图默认独立有头浏览器 + CDP，缺少能力时停止，只有用户明确选择备用模式才使用星图内嵌任务浏览器。之前的单次报告观察到 WebView2/GPU 页面用 BitBlt/PrintWindow 抓不到内容；不要重复写这些脚本或枚举窗口句柄。
- 如果当前已授权的浏览器工具提供 CDP 截图并能直接将结果写文件，可使用该能力；不能假定调试端口、tab ID 或本机文件导出必然存在。
- 若浏览器导出与已安装 FFmpeg 的单帧测试均不可用，报告缺少“浏览器图片到本机文件”能力，交维护者配置适配工具。不要为了小体积把图片缩到文字不可读。

独立浏览器的协议截图与桌面抓屏是不同路径。CDP 不保证页面不会冻结；FFmpeg 也不能解决窗口最小化。恢复窗口或调整大小后，重新确认任务页和截图范围。

## 本机 FFmpeg 直接抓屏（受支持的替代路径）

用户报告星图所在电脑已安装 FFmpeg 7.1.1，计划测试直接抓屏；这是待验证方案，不代表所有设备已装，也不代表已经验证能抓到 WebView2。模型不得接收、转录或拼接截图 Base64；由 FFmpeg 将像素直接写入 PNG 文件，上传时由 client.py 编码。

1. 用本机执行工具检查 `ffmpeg -version`、`ffmpeg -hide_banner -devices`，确认当前构建包含 Windows `gdigrab`。若没有该设备或权限，不安装新组件、不要轮换抓屏库。
2. 通过当前可用的浏览器/桌面工具确认任务窗口及可见回答区域；保持它在前台、未最小化且无遮挡。只捕获已确认的任务区域，不默认抓整个桌面。不要猜测窗口标题或坐标，也不要用脚本枚举无关窗口。无法确认范围时停止并说明。
3. 依据本机 `ffmpeg -h demuxer=gdigrab` 确认参数。下面为参数模板，X、Y、WIDTH、HEIGHT 必须替换为实际确认的任务内容区域，输出改为授权证据目录内的新文件：

```text
ffmpeg -hide_banner -loglevel error -nostdin -n -f gdigrab -framerate 1 -offset_x X -offset_y Y -video_size WIDTHxHEIGHT -draw_mouse 0 -i desktop -frames:v 1 -update 1 "任务证据目录/answer-01.png"
```

只截一帧，不录屏、不采集音频；通过执行工具设定不超过 15 秒的超时。也可使用已确认的任务窗口 `title=实际标题`，但需检查截图是否含无关侧栏并限定上传区域。文件由程序落盘后，读取文件确认文字可辨、无黑屏/遮挡、题目与回答对应；仅文件存在不算成功。不要把此路径称为一定能绕过 GPU 黑屏。

4. 成功后记录所用 FFmpeg 路径、抓屏区域和目录，同批复用；窗口位置或尺寸变化时重新确认区域。失败仍遵守整个排查最多两条路径、三分钟的限制，不反复试错。

FFmpeg 官方设备说明：https://ffmpeg.org/ffmpeg-devices.html#gdigrab

## WorkBuddy

- 先查看当前可用的浏览器/截图工具或已安装的浏览器 Skill，读它自己的工具说明，优先截图直接输出到任务工作目录；没有该能力时不要把它当成已经安装，也不要顺便安装扩展。
- 已生成文件可在 WorkBuddy 的“产物 / 全部文件”检查实际位置。官方说明支持查看工作空间产物，但这不等于所有版本的截图工具都能直接落盘。
- 若工具在远程环境生成文件，只能按客户端明确支持的下载方式保存到参与者电脑，再验证 client.py 可读取。不能把远程 `/tmp/...` 当成本机路径。

## 文件组织与上传

建议使用已授权工作目录下 `geo-evidence/<项目编号>/<assignment_id>/`，文件命名 `answer-01.png`、`answer-02.png`、`sources-01.png`，样本保存为 `sample.json`。示例中的目录不是要求访问额外目录；以用户实际授权范围为准。

截图仅覆盖当前任务问题、回答和必要引用。优先按 [高效采集指南](fast-collection.md) 使用经过首题验证的元素截图；有裁剪、内部滚动或长图不可读时分段且有少量重叠。最多 20 张，总包上限 5 MB（含 Base64 膨胀），优先去除无关空白和重复区域，再适度 JPEG 压缩；可读性优先，不固定使用 0.35 倍或极低质量。

在 sample.json 的 screenshot_paths 填写实际路径，例如 `["answer-01.png", "sources-01.png"]`；相对路径按 sample.json 所在目录解析。执行 `python scripts/client.py validate --file sample.json`，通过后 submit。不要反复向模型展示截图编码。

同一客户端版本和会话验证过的方法，本批直接复用；成功后简短记录工具名、保存方式和目录，不记录 Cookie 或令牌。升级客户端、换工具或路径失效时才重新检查，不每题重新探索。

官方参考（仅用于确认 WorkBuddy 文件结果区，不承诺具体截图 API）：https://www.codebuddy.ai/docs/zh/workbuddy/Results
