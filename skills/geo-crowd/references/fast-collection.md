# 高效采集：首题确认，整批复用

## 适用范围与验证成本

依据参与者提供的 WorkBuddy 本地测试报告整理：该环境支持 async eval、eval --filename 输出 JSON，以及元素截图。维护者未在该参与者电脑重跑；Node 每次启动耗时 2–3 秒、Bash 结束杀守护进程是该环境观察，不是所有客户端的机制。不承诺每题固定两次调用，也不把离线测试当作真实平台验收。

先读当前客户端已有工具帮助，优先复用会话内原生浏览器工具与已验证的方法，不为这些技巧安装或替换浏览器。只有能力未知时做一次小探测；首题确认当前平台定位与证据范围，后续复用。原有截图排查“两条路径、三分钟”预算保持不变，不额外再开一轮测试。不要每题查看帮助、启动新浏览器或造解析脚本。客户端版本、布局变化或原路径失败才重新检查。

## 1. 合并等待调用，但不能把旧回答当作生成完成

工具支持 Promise / async 时，可把只读状态检查放在一次有界 eval 中，每秒检查一次；单次等待不超过 45 秒且小于实际工具超时，必要时返回进度后继续等待，总等待预算默认 180 秒。到期返回“未确认完成”，保留当前对话，不重复发送问题。不能用网页后台定时器保证现实时间或认为 hidden 页面一定正常工作。

完成判断必须绑定本题：
- 发送前记录当前会话与最新回答节点；发送后确认本题原文真的出现在对话中。
- 找到与本题对应的新回答；不能只检查页面存在任意 .ds-markdown。
- 仅在当前回答/会话范围检测可见的生成中、停止按钮或 aria-busy。隐藏的旧按钮与其他会话无关。
- 结合平台已观察到的完成状态（例如当前回答的复制/重试操作出现、生成状态结束）确认完成。停止按钮消失本身不够：断网、报错、验证码、中断也会让按钮消失，须排除这些状态。
- 文本长度短暂不变只作辅助，不能单独判结束。正文结束后再检查引用面板与引用数量；来源可能晚于正文出现。

不要照抄报告里的 div/button/span 全页扫描；优先已确认的语义定位和当前回答容器。类名 .ds-markdown、._26c5bc2 只是来源报告中的示例，不是跨版本契约。

## 2. 原始 JSON 由工具直接写文件

当前 CLI 帮助确实支持 eval --filename 且一次最小对象试验确认是纯 JSON 时，直接把提取结果写到本机任务目录的 extract.json。若支持的是其他输出参数，使用实际接口，不猜同名参数普遍存在。JSON 必须由程序解析校验：顶层对象、当前题目与回答、引用字段；不得用正则剥掉不明包装或模型转录大段 JSON。若输出是字符串包装，仅依据已验证格式解析，不对任意文本反复 JSON.parse。

eval 的返回文件通常只是提取数据，不等于完整上传 sample.json；用程序补齐本次 assignment_id、采集条件与本机截图路径，再执行 client.py validate 和 submit。保存原文，不因压缩调用次数省略引用。成功方式整批复用；不可用则使用现有工具支持的程序写文件，不反复尝试不存在的参数，不弹出“另存为”让用户逐题处理。

## 3. 回答正文优先元素截图

当前工具支持元素截图时，选中本题完整回答容器并直接落盘。普通长元素可能得到超出视口的完整截图，但祖先裁剪、内部滚动、虚拟列表、懒加载和工具图像尺寸上限都可能造成缺失。首题检查顶部、中部、底部与正文首尾；后续至少核对本题边界及文件可读性。不因为图片很长就认定内容完整。

截图仅回答正文时，还需补充本题问题对应的证据图或选择包含问题及回答的任务容器。不能只凭 .ds-markdown 截图证明回答归属。长图过大或文字不可读时回退分段，保持少量重叠；遵守最多20张及总包5MB限制，不把文字缩成不可读小图。不默认使用 full-page：先确认不会包含其他会话侧栏或无关内容。

## 4. 来源面板要处理内部滚动

元素截图不会自动展开内部滚动区域。默认先按原始界面展开来源，再在来源容器内滚动采集，核对序号、标题、实际链接与可见总数；虚拟列表须逐段读取，不能只读当前 DOM。适度增高任务视口可减少滚动，但要重新定位并确认布局与内容均加载完成。

不默认改 height / overflow 来采集正式证据。仅当项目明确允许调整布局证据时，才可暂时解除裁剪：先保留未修改原图，记录修改字段与原因，保存原值，完成后在 finally 恢复；调整后的图命名 sources-expanded-layout.png 并在 completeness_notes 注明“布局调整，内容未编辑”。不能增删、改写文本和链接，也不能把调整图作为唯一证据。调整布局不会自动加载虚拟/懒加载内容。

## 固化本机已验证路径

在任务工作目录留一份简短能力记录：客户端与工具版本、浏览器会话标识、等待与定位方式、JSON 保存方式、截图方式及保存目录、首题验证时间。不要记录 Cookie、绑定码、令牌或无关个人路径内容。新批次先复用记录；失效才做有界回退。

这些优化只减少工具往返和重复定位，不能跳过每7题休息5分钟、默认完成全部已领题目、平台限流暂停及证据完整性要求。

参考：Playwright 官方元素截图说明 https://playwright.dev/docs/screenshots ，CLI 文档 https://github.com/microsoft/playwright-cli 。具体命令参数始终以当前工具帮助为准。


## 星图采集经验：可以直接复用的流程规则

以下来自参与者的星图采集报告，经规则层面整理，未在其设备复测。Skill 当前没有自带 `_tools/geo_doubao.js`、通用采集执行器或已验证的平台选择器配置；这些名字不是可执行入口。不要为了满足“一题一命令”临时开发大量脚本、安装依赖或声称功能已存在。已有本机适配器且来源、接口、权限明确时可以复用；否则使用客户端现有工具按下面规则减少往返。

### 合并操作与阶段恢复

合并当前工具明确支持、范围明确的连续步骤，例如同次提取正文、引用和页面条件并直接落盘；使用已有浏览器会话，避免每一步重新启动浏览器。不要把一个超长且不可恢复的命令作为必需条件，也不要为了保持进程绕过客户端的宿主机权限或生命周期限制。

在本题任务目录保留简短进度记录：assignment_id、题目、已发送的会话URL、阶段、证据路径、上传回执。阶段依次为：已领取、已确认发送、回答完成、引用已提取、证据已保存、校验通过、提交已确认。只记录已真实完成的步骤；不要把标记当成自动断点恢复已经实现。

恢复时先核对服务端与本地回执，再继续原会话：上传失败只重试上传；截图失败只补截图；引用缺失只补引用。发送结果不确定时先检查本题是否已在对话里，不能再次点击发送。已提交题不得为提速重新生成回答。批末列出成功、失败及剩余题号；未完成时仍可释放，但不能报告整批完成。

### 先测量再截图，整批保持合理视口

首题确定可读且不包含无关会话的任务视口，后续复用，不在截图命令中临时改变尺寸。不默认采用1920×5200、deviceScaleFactor=2；高像素会增加截图、编码和上传成本。固定视口不保证布局永远稳定：正文、字体和引用加载后仍可能改变尺寸。

用当前回答容器的实际几何范围计算截图区域，优先元素截图；需要分段时按可见区域计算步长并保留重叠，减少探索性整页截图。首题确认工具坐标使用的是视口还是文档坐标、是否需要考虑缩放；滚动或布局变化后重新测量，不复用失效坐标。内部滚动和虚拟列表仍遵守前文完整采集要求。

### 自动检查与视觉核对分工

已有本地工具能直接检查时，自动核对文件可读取、PNG/JPEG格式、尺寸、体积、重复图、预期分段是否齐全。黑白像素比例只能提示疑似空白或黑屏，不能证明文字可读、题目对应、横向未裁切或引用完整；深色主题也不能按黑屏直接拒绝。

首题完整核对截图方法；后续每题轻量核对题目归属、正文首尾、截图覆盖与引用缺项，疑似异常再逐张查看原图。不无理由反复读同一批图片，也不能把“仅首题和最后一张看图”当成所有平台充分验收。

### UI定位与元数据复用

缓存已验证的语义定位、备用选择器、引用容器与解析方式，并记录平台、工具版本和验证时间。每题使用前检查目标唯一性、可见性和本题归属；不匹配时只做一次有界重新定位，不能盲点旧坐标。优先角色、标签与当前会话范围，动态类名只作备用。

自动生成 sample.json 时只使用实际观察：平台入口来自任务；模型、联网状态和搜索关键词来自页面明确展示；无法确认记 unknown 或契约允许的缺省值，不根据模式名或另一题推断。只有明确搜索关键词区域中的内容才能记作关键词，不能把任意引号列表当成关键词。保留原始回答与引用URL，校验后逐题提交。

### 节奏与耗时记录

同一账号同一平台串行采集。新版 GEO 由客户端按 pacing.json 执行每7题休息300秒；若服务端实际返回 retry_after 仍应遵守。没有 retry_after 只代表本次未触发 GEO 等待，不能证明耗时全来自工具。

每7题休息300秒、默认完成全部已领题目以及用户指定范围的规则继续生效。复用专用浏览器登录态；登录过期、验证码或限制出现时暂停，不承诺永久零人工。

如现有工具支持，按题记录发送、生成等待、引用、截图、校验上传与工具调用次数，另计批间休息；无法测量的耗时标记未测，不虚构拆分。1.5–2.5分钟/题只是参与者提出的目标，未获验证，不作为完成时限承诺。
